# Selected-program experimental owner Send — internal integration

Program **Send** now compiles and sends the actual selected library records in selection order, never substitutes a fixed test pattern. A separate **Static orientation test (experimental)** retains the previous dim corner pattern and consent. Existing internal `SmartEaseNativeUX.send()` remains that orientation entry for backward compatibility; `sendSelected()`/Program Send is the actual playlist path.

Local Save, copy, library import/export and opening/compiling a Send dialog never transmit. Five fresh owner confirmations cover known UX16×96 target, parked potentially animated/authored-brightness operation (NOT a dim-test claim), original-app restore readiness, overwrite/partial-state risk and ACK ambiguity. Displayed program count/names/types/repeats are captured literal text. Cancel cannot undo writes already transmitted. No assistant BLE was used; mock ACK tests are not physical acceptance.

All selected Text/Graffiti/Clock/source-admissible Animation03 records compile before any subscription/write. Unknown kinds or ambiguous raw/staleGIF Animation branches reject the WHOLE selection without fallback protocol. Text uses existing original font/emoji loaders. Clock serialization includes its original background/clock layers; no clock synchronization or OTA chain is introduced. Compiler source is independently reviewed; dependencies are loaded before their consumers. Original firmware/GIF branch gates remain explicit.

Identity and lifetime: exact canonical captured library (including unknown metadata and selection order), route epoch, device identity/generation, characteristic and write/notification capabilities are checked through compile and every uploader action. Main openSelectedSend synchronously calls cancel(), invalidating any older pending JSON file-read guard. Starting library import or another dialog closes selected Send before its own await; route/hide/reconnect/Back also synchronously leave. Forward or reopening clears consent. Async admission status updates use the captured outer guard rather than repainting another route.

The existing `ux-owner-send.js` module owns the ONLY link WeakMap lease. Selected controller acquires it once for the entire playlist; per-program uploader leases are borrowed and cannot release it. This prevents orientation interleaving between programs and retains ownership through pending cancellation/subscription/write settlement. Advance only after each reviewed uploader reports complete, including source cached-CRC completion; failures halt the rest with a partial-state warning. Original20-byte fragments, pacing and no-auto-retry are unchanged. An ACK sequence is not proof of pixels/order/retention, and delayed matching ACKs remain intrinsically ambiguous.

Capacity evidence: default9 is native source fallback, NOT measured capacity. Compiler permits explicit bounds up to99, but current main passes no invented device capability. Logical packet256 is the earlier conservative experimental setting, NOT source1024fallback, measuredMTU orATT size. No automatic1f/device-info query, inferred geometry/version or new device-setting writes.

Main tests cover actual ordered cachedACK playlist and unchanged local data, both JSON-import overlap directions, route/Back/reconnect cancellation, fresh confirmations, sharedlease mutual exclusion in both orientations, pending write quiescence, unsupported whole-selection rejection and exact dependency/cache ordering. Existing compiler/controller tests remain portable in CI; source asset/vector provenance lives in the private development archive. Bluefy owner device acceptance and a reviewed/publication-authorized full candidate remain separate.

Global full-backup restore is also mutually exclusive with these admissions. A nonempty restore synchronously cancels UX selected/orientation transfers through a narrow hook, then captures a global restore epoch. The file result is checked after await, before confirmation and before each storage write; stale errors/finally callbacks cannot repaint or clear a newer file selection. Native navigation/new admissions revoke pending restore, whereas idempotent inactive UX leave/device refresh in Settings does not. Pending writes retain the same shared lease until settlement. Existing restore schema limits (including the1MiB Lotus group bound), confirmation Cancel and transactional rollback are unchanged; no new device disconnect is added to admission cancellation.
