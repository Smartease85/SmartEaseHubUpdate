# Authored Lotus controls and rhythm illustrations

This checkpoint independently authors all **70** non-scene/non-hardware runtime art assets: 54 PNG controls/palettes and 16 animated rhythm demonstrations. The old bottom-bar source-art contact sheet is replaced by a generated inspection sheet as well. Complete geometric source: `tools/generate-lotus-controls.py`; dimensions, transparent bounds and animation timeline contracts: `tools/lotus-control-contracts.json`; current hashes: `assets/native-lotus/authored-controls-provenance.json`. The generator reads no original images, original glyphs or APK, and uses no downloaded artwork. GIF and PNG encoding use installed Pillow.

## Functional and visual contracts

* Every original filename/URL, raster size and transparent outer bound is retained. No selector or mode is removed. Bottom tabs, power buttons, scene/mode/music/palette/schedule meanings, selected red-blue gradient versus inactive gray, warning yellow, theme toggles, music transport, menu-style previews and beehive menu positions are retained. Geometry is newly authored; glows and complex curves are simplified, not original-pixel parity.
* The two sampled color palettes are actual mathematical hue/saturation disks, not decorative approximations: default `ic_palette_bg` uses clockwise red→magenta→blue→cyan→green→yellow; alternate `ic_big_solorwheel` uses the reverse orientation. Both have white centers and red at the right. The separate RGB/ring switch previews retain their muted purple-right/red-bottom/yellow-left/green-top arrangement. New anti-aliasing/interpolation may change individual sampled byte values near edges; RGB entry, swatches, geometry and command handlers are unchanged. No exact original sampled-byte claim is made.
* All eight Device MIC mode choices retain two theme variants. Independent serpent-strip geometry distinguishes expanding Energy, alternating Rhythm, segmented Spectrum and traveling Scroll, with one/two color behavior variants. Original dimensions, loop settings, 50ms timeline steps and **total animation durations** are preserved. Encoders can merge identical adjacent frames into multiples of 50ms; the manifest records actual frame count/durations plus source timeline count/duration. These are UI demonstrations, not a claim of controller waveform/output parity. The DSP, mode commands, audio/permissions, transport and lifecycle code are unchanged.
* No generic repeated placeholder, missing art slot, bundled third-party font, or external fetch is introduced. Metadata no longer claims replacement bytes came from an APK. UI changes outside art are explanatory text only.

## Consumers

`native-lotus-bottom.js`: 12 bottom/power PNGs. `native-lotus-menu.js`: 17 beehive/style PNGs. `native-lotus-mode-style.js`: three mode-style PNGs. `native-lotus-setup.js`: two theme toggle PNGs. `native-lotus-functions.js`: warning PNG. `native-lotus-library.js`: add PNG. `native-lotus-color.js`: both actual sampled palettes plus two switch previews. `native-lotus-diy.js`: default sampled palette. `native-lotus-rhythm.js` and `native-lotus-rhythm-data.js`: 14 music/tab PNGs and eight dark GIFs, with packaged light counterparts kept compatible. `sw.js` retains cache URLs. Existing runtime numeric controls and accessibility labels are not redesigned.

Existing functional assertions remain; only provenance wording is updated where art origin changed.

This is offline structural/art validation, not full rendered browser, iOS pixel parity, physical controller acceptance or deployment. Only the checkpoint overlay manifest should be integrated. Do not publish the whole reference checkout or private analysis history.
