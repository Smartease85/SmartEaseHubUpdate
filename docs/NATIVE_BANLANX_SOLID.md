## Explicit browser safety/domain differences

Control routes require an explicit current-connection complete status read; no automatic read/write, saved-state authority or assumed ON. Direct links also require selected outputs verified ON. Entering control does not carry stale Channels proof. Own queued writes invalidate readback proof without invalidating their own remaining guarded sequence. External writes, malformed/new fragments, route changes, identity/generation, hidden state, consent revoke/recheck and late callbacks cannot revive old queued intent.

Reported RGB is calibrated wire data, NOT reconstructed authored H/S. Current circle/hex shows reported raw RGB. Until complete RGB/preset choice, hue/saturation and multi-output brightness stay unavailable. Single-output brightness alone sends unchanged raw reported RGB plus newB, with no gain, normalization or chip-order rewrite. The disabled hue/S controls use a neutral placeholder rather than claim recovered authored hue; the notice labels this intentional calibration guard. No inverse-gain/clipped preimage or silent raw-vendor bypass exists.

Consent is an extra browser control, not original UI. It is checked before enqueue, so stale/busy requests cannot stop unrelated playback. Keyboard controls, asynchronous draft/error handling, accessibility focus, lifecycle cancellation and unsupported-canvas fail-closed behavior are browser adaptations. Resizing recreates geometry using explicit browser ambient width/375 and height/667, retains draft and revokes old consent/operations. This differs from a proved original browser safe-area contract, which does not exist.

## Storage and backup

Key `smartease-native-banlanx-diy-v1`: format/version1, devices keyed by exact identity, sparse known slots0…6 containing rgb. Missing entries read defaults without writes. Canonical single-set storage preserves unknown root/device/slot metadata and other devices. Malformed/future records remain untouched and fail closed; no migration of unrelated libraries. Full backup validates all entries and this key's complete schema/1MiB UTF8 limit before mutation. Browser localStorage lacks cross-tab compare-and-swap; atomic here means synchronous validate/modify followed by one setItem, no optimistic cache.
