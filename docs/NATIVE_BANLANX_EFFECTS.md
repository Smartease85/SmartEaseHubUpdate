## Protocol and state

Route, identity/session, pending Back, mode, visibility, consent revocation and exclusive queue guards are checked before enqueue and at dispatch. Own packets are registered with the shared control host; stale requests cannot interrupt unrelated playback. No automatic read,83,85,89 or power action occurs on mode/body creation. Explicit mode actions retain existing source25 Solid entry and remembered decoded effect return.

Source record offsets: speed4 upper-clamp10, length5–6 BE upper-clamp240, reverse7==0, brightness3, RGB8–10. Speed/length0 are not invented as1: the browser marks those controls unknown. Global sensitivity is byte88, not channel-specific; absent/out-of-range1–16 remains unknown and never uses stale cached gain. Fresh verified Effects reads replace brightness with first selected current brightness and clear authored inference; Solid's existing draft contract is separate.

Effects commands:83 effect,85 brightness,86 speed,87 BE16 length,8A inverse reversed boolean,8B sensitivity. Effects brightness sends85 only for any mask: unlike Solid89 it never carries/unifies RGB and therefore does not require authored color for multiple outputs. Music disables brightness. Capability lists use display-index+1, not musical protocol IDs101–116.

Palette or disk sends authored V1 target through source-order normalization, then each output calibration once and requested first-selected brightness. Reported wire RGB is never normalized into an inferred authored target. Disk is disabled until a complete palette color establishes authored intent. Effects color operations never update a hidden selected Solid DIY record. Color and numeric drafts are not reported device acceptance.
