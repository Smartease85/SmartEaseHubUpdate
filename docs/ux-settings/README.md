## Runtime

`settings-controller.js` imports **the actual main** `ux-owner-send.js` binding, not a second copied lease registry. It uses that binding's current identity/generation/characteristic and `ux-experimental-uploader.capability`. Thus owner-pattern/program uploads and Settings reads/writes contend on the same link-scoped exclusive lease. Browser consumers must load the existing Owner/Uploader globals once, then source codec, device-info, controller and UI. Main integration must not create a separate Owner module instance.

Controller `create({adapter,valid,onState,scheduler,timeoutMs:5000})` exposes `run(intent,consent)`, `snapshot`, `refresh`, `cancel`, `dispose`. `valid()` must include active route/view and document visibility. Host connection/context events must call `refresh()`. The isolated UI owns visibility/pagehide/history/Back listeners. Compose with `let ui; const controller=create({... onState:()=>ui?.render()}); ui=UI.create(host,{controller,valid,...});`. UI exposes render/leave/dispose. Device reconnect needs a new explicit admission; rendering never writes or reads. Only host-owned source objects are accepted; this is not a BLE connection/discovery API.

Intent kinds: read; brightness5..255; rotation0..3; power boolean; showDeviceId boolean; remoteEnabled boolean. Power controller support is for the original parent Program/Material/Discover control; **Settings does not render power**. Consent requires parked:true, explicit:true, current deviceId, generation and opaque admission revision from snapshot. The revision is re-evaluated on run/snapshot/refresh and changes on observed disconnect, capability loss, characteristic replacement or view invalidation; old tokens cannot authorize a later recovered session. Unknown booleans cannot be toggled implicitly. UI offers explicit On/Off selections. Device actions wait for one bounded corresponding reply, with no retries. Pending slider events are intentionally serialized rather than reproducing native queue/broadcast behavior.

The epoch is captured before observer callbacks; each asynchronous boundary rechecks context. Cancellation/timeout removes only this operation's listener/timer and prevents further writes. The exclusive lease remains held until an already-started subscription/write settles, even after cancellation or timeout; a permanently unsettled platform promise intentionally blocks another operation. We never stop shared notifications or clear another uploader's queue. Early replies are staged until write settlement; failed-read early state is discarded before another session can inherit it.
